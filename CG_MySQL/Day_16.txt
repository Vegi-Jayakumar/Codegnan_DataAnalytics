mysql> /* TCL and Constraints
   /*> Transaction: the process of combining all related operations into a single unit and executing them according to the rule("either all or none")
   /*> example: funds transfer
   /*> two operations: debit from sender's account, and credit from receiver's account should be successful or fail together
   /*> if one succeds and other fails, it leads to data inconsistency problems.
   /*> 
   /*> There are two types of transactions:
   /*> 1. local transactions
   /*> 2. global transactions
   /*> 
   /*> 1. local transactions: here, all operations of a transaction are executed on the same database.
   /*> eg: funds transfer from one account to another account where both accounts belong to the same bank.
   /*> 
   /*> 2. global transactions: here, all operations of a transaction are executed on different databases.
   /*> eg: funds transfer from one account to another account where the accounts belong to different banks.
   /*> 
   /*> ACID properties
   /*> A - Atomicity: all or nothing
   /*> C - Consistency: The database remains in a valid state
   /*> I - Isolation: transactions do not interface with each other
   /*> D - Durability: committed changes are permanent
   /*> 
   /*> Transaction Control Language commands: 
   /*> 1. commit
   /*> 2. rollback
   /*> 3. save point
   /*> 
   /*> commit: it is used to permanently save all changes made during the current transaction into the database.
   /*> once committed: changes become permanent, other users can see the changes, you cannot undo the changes using rollback.
   /*> 
   /*> rollback: it is used to undo all changes made in the current transaction before a commit.
   /*> if something goes wrong, rollback restores the database to its previous state.
   /*> */

mysql> /* Stored Procedures
   /*> It is a named and precompiled collection of one or more SQL statements that is stored inside the database and can be executed, called whenever required instead of sending long block of SQL from an application every time, the application simply calls the procedure by name.
   /*> 
   /*> Why use stored procedures?
   /*> 1. performance
   /*> 2. reusability
   /*> 3. security
   /*> 4. reduced network traffic
   /*> 5. maintainability
   /*> 6. consistency
   /*> 
   /*> advantages
   /*> 1. faster execution after completion
   /*> 2. reduced duplicate sql
   /*> 3. supports transaction, loops, conditions, variables, ... etc
   /*> 4. easy maintenance
   /*> 
   /*> disadvantages
   /*> 1. debugging can be difficult
   /*> 2. vendor specific syntax
   /*> 3. complex procedures may become hard to maintain.
   /*> 
   /*> syntax:
   /*> DELIMITER //
   /*> create procedure procedure_name()
   /*> begin
   /*>  --- sql statements
   /*> end //
   /*> DELIMITER;
   /*> 
   /*> IN paramater: it is used to pass a value into a stored procedure.
   /*> the procedure can use the value, but changes made to the parameter inside the procedure are not returned to the caller.
   /*> 
   /*> syntax:
   /*> create procedure procedure_name(IN parameter_name datatype)
   /*> begin
   /*> 	sql statements
   /*> end ;
   /*> delimiter ;
   /*> */
